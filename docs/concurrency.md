# Concurrency

- `get()` and `get_batch()` are thread-safe and release the GIL. For `method=1`/`2`, calls on one variable of one store take turns (per-variable lock); for parallel reads give each thread a [`fork_reader()`](api-pyddstore.md#fork_reader), as `ThreadDataLoader` does.
- `method=0` `get_batch()` is **collective**: same number of calls, same order, one thread per rank. `vae-ddp.py` allows no workers with `method=0`.
- MPI thread level: `FUNNELED` is enough when only the main thread calls DDStore with `method=0`. `ThreadDataLoader` reads on a worker thread (also with `num_workers=0`), so `method=0` with it uses exactly one worker and requires a provided MPI thread level of `SERIALIZED` or higher (check with `MPI.Query_thread()`; the requested level or mpi4py's default `MULTIPLE` doesn't prove what MPI provides). With `SERIALIZED`, no other thread may call MPI while the loader reads, on any communicator. With `MULTIPLE`, other threads may call MPI meanwhile, on any communicator: the loader's exchanges run on a private duplicate of the store's communicator, made by `add()`, and make no collective on the communicator passed in. Methods 1/2 make no MPI calls when reading.
